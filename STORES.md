# BranchForge & HaulCrest — UK equipment stores

Two independent single-niche storefronts, each with two products priced over £2,000
and aimed at the UK market.

```
branchforge/     branchforge.shop — tree & land clearing
  Cyclone 150 TD Wood Chipper        £2,899  (was £3,699)
  Grindmaster 380 TX Stump Grinder   £3,449  (was £4,299)

haulcrest/       haulcrest.shop   — hauling & earthmoving
  Titan 1000 HT Tracked Dumper       £2,699  (was £3,499)
  Vanguard 850 SL Compact Loader     £3,299  (was £4,199)
```

Each site is static HTML/CSS/JS with no build step and no dependencies, and contains:
home, two product pages, about, contact, order tracking, policies, `sitemap.xml`,
`robots.txt` and a `CNAME`.

## Product imagery

Every product has **8 images** in `assets/img/<product>/`:

| File | View |
|---|---|
| `01-hero` | Full machine, dark studio |
| `02-side` | Side elevation, light studio |
| `03-*` | Working-end detail (infeed / cutter / high tip / bucket) |
| `04-engine` | Power unit with cutaway panel |
| `05-controls` | Operator controls |
| `06-dimensions` | Dimensioned technical drawing |
| `07-in-use` | On-site scene |
| `08-included` | What ships in the crate |

The images are original SVGs generated by the scripts in `tools/`, not sourced from
any third party, so the **only** branding on any machine is the brand of the site it
belongs to — `BRANCHFORGE` or `HAULCREST`, plus that machine's model decal.

Regenerate them with:

```bash
python3 tools/gen_bf1.py    # Cyclone 150 TD
python3 tools/gen_bf2.py    # Grindmaster 380 TX
python3 tools/gen_hc.py     # Titan 1000 HT and Vanguard 850 SL
```

### Swapping in photographs

To replace an illustration with a real photograph, overwrite the file in
`assets/img/<product>/` keeping the same name (a `.jpg`/`.png` works — update the
`src` in the product page and the `data-full` on its thumbnail). Use a 1200×760
(≈16:10) crop so the gallery keeps its aspect ratio. Alt text lives in
`tools/cfg_branchforge.py` / `tools/cfg_haulcrest.py` under each product's `images`.

## Rebuilding the pages

Page content lives in the two config files; the shared template is `tools/build_site.py`.

```bash
cd tools && python3 -c "
from build_site import write_site
from cfg_branchforge import CFG as BF
from cfg_haulcrest  import CFG as HC
write_site(BF, '../branchforge'); write_site(HC, '../haulcrest')"
```

## Run locally

```bash
python3 -m http.server 8000     # then open /branchforge/ or /haulcrest/
```

## Deploying to the two domains

GitHub Pages serves **one** site per repository, so these two cannot both go live from
this repo as-is — the root `CNAME` (currently `skillore.shop`) wins. Each store folder
already contains its own `CNAME`, so pick one of:

1. **Separate repos (simplest).** Copy the contents of `branchforge/` into the root of a
   repo published at `branchforge.shop`, and `haulcrest/` likewise. The `CNAME` in each
   folder is already correct.
2. **Any static host** (Netlify, Cloudflare Pages, Vercel): point one project at
   `branchforge/` and another at `haulcrest/` as the publish directory, and set the
   custom domain there.

In both cases add the DNS records your host asks for on each `.shop` domain.

## Not wired up

The contact, enquiry and order-tracking forms are front-end only — they validate and
confirm locally but send nothing. No payment processing is present, and the product
pages say so rather than implying a live checkout. Connect a form handler and a payment
provider before taking real orders.
